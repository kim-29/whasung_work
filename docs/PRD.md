# PRD: 알루미늄 대리점 주문·작업 관리 앱 (v0.1 초안)

## 1. 배경 / 목표
- 대리점(프론트)이 고객 요구를 접수 → 작업장에 오더 전달 → 작업장이 절단/제작 → 무게 입력·완료 → 프론트가 수금(납입) 관리.
- 사용자는 컴퓨터에 서툴 수 있음 → **큰 버튼, 적은 단계, 쉬운 한글 용어**가 최우선.
- 기대효과: 프론트=진행현황 모니터·미납/완납 확인·자재 사용 모니터링(부족 자재 신청) / 작업장=정확한 오더 수령·도면 확인.

## 2. 사용자 / 권한
| 역할 | 접근 | 기기 | 인증 |
|---|---|---|---|
| 관리자(사장) | 직원 권한 + 직원/PIN/기기 관리, 작업장 PIN 변경 | PC/태블릿/폰 | 6자리 PIN (최초 관리자 PIN은 서버 Secret) |
| 직원(프론트) | 대시보드·작업지시서·작업목록·bar_database | PC/태블릿/폰 | 직원별 6자리 PIN, 관리자가 발급 |
| 작업장 | 작업목록 화면만(무게 입력·완료·도면 보기) | 태블릿/폰 | 공용 6자리 PIN, 최초 1회 입력 후 기기 토큰 자동 로그인 |
| Blender 연동 | 서버 입력 API만 | PC(인공지능 경유) | API 키 |

## 3. 시스템 구성 (확정)
- **프론트**: 정적 SPA(모바일 우선 반응형, PWA) → GitHub Pages 배포.
- **서버**: Cloudflare Workers (REST API + 알림).
- **D1**: `bar_database`, `work_list`(+ 아래 제안 테이블) / **R2**: 3D 도면 HTML / **KV**: 환경설정(회사명, 알림 설정 등).
- **실시간 알림(제안)**: 무료 조건 + 화면 꺼져도 수신 → **Web Push(VAPID, Workers 무료) + 화면 켜진 동안 WebSocket(Durable Objects, 무료 플랜 SQLite DO)** 병행.
  - Android/PC: 바로 동작. **iPhone은 홈 화면에 앱 추가(PWA) 후에만 푸시 수신(iOS 16.4+)** → 설치 안내 화면 필요.
  - 대안(앱 설치 부담 시): 텔레그램 봇 알림(무료·가장 안정적).
- 금액: **DB에 저장하지 않음** (확정). 견적서의 kg당 가격×무게는 화면 내 실시간 계산·표시만.
- Blender 연동: **API 키 + JSON 절단서 + 단일 HTML 도면, 블렌더에서 보내면 곧바로 확정 오더** (확정). 미리 코드를 만들어 두고 AI(OpenCode)가 그 코드를 실행해 전송.

## 4. 데이터 모델 (초안)
- `bar_database`: id, 바 이름, kg당 무게(kg/m), 단위/비고, (제안) 현재 재고·최소재고.
- `orders`(제안, 작업지시서 헤더): id, 요구업체명, 작업구분(절단/제작), 별도요구사항, 도면파일(R2 key), 상태, 지시일, 완료일, 납입여부, 납입일, 작성자/출처(front|blender|manual).
- `work_list`(절단서 행): order_id, 바 이름, 길이, 수량, 색상, 무게(실측), …
  - 무게는 **오더 총합 1회** 입력(9절). work_list에는 이론무게만 저장.
- 상태: `대기 → 절단중 → 절단완료(무게입력) → (제작만) 제작중 → 제작완료 → 미납 → 완납`.
  - 절단작업: 무게 입력 확인 시 즉시 미납 이동. 제작작업: 무게 입력 후 제작완료 버튼 시 미납 이동.
- `users`: id, 이름, 역할(admin/staff/workshop), pin_hash(HMAC), 활성 / `devices`: 기기 토큰 해시 / `audit_log`(제안): 수정자·변경 전후(무게/업체명 수정 이력) / `push_subscriptions`(제안).

## 5. 화면 요구사항
### 5.1 공통 UX 원칙
큰 글씨·큰 터치 영역, 하단 탭 4개(대시보드/작업지시서/작업목록/설정), 한 화면 한 가지 일, 위험 동작(삭제·납입)은 확인창, 입력값 즉시 검증, 오류는 쉬운 말로.

### 5.2 대시보드 (프론트, 조회+수정)
1. **미납 거래내역**: 요구업체명, 작업지시일, 작업완료일, 색상/무게, 세부내역(클릭→상세), 도면(클릭→3D 뷰), **[납입] 버튼**(완납 처리 + 납입일 저장). 납입 전 업체명·무게 등 수정 가능.
2. **월간 거래내역**: 월 선택, 건수/총무게/납입·미납 현황.
3. **기간별 자재 사용내역**: 기간 선택, 바 이름별 사용량(길이×수량·무게) **많이 쓴 순 정렬**, 재고 부족 자재 표시 → 자재 신청(방식 미정).
4. **업체별 미납 명세**: 업체 선택 조회 + **인쇄/PDF 출력**.

### 5.3 작업지시서 (프론트)
- 입력: 요구업체, 작업구분(절단/제작), 작업내용, 별도 요구사항, **절단서 표**(바 이름[bar_database 선택], 길이, 수량, 색상 / 행 추가·삭제), 도면 첨부(제작 시 필요하면).
- **견적 표시**: 입력 즉시 총 무게(kg) 표시, kg당 예상가격 입력 시 총액 표시(저장 안 함).
- [전송] → 서버 저장 + 작업장 알림. 전송 성공 시 큰 확인 메시지.
- 작업장 수기 접수 건: 프론트가 '수기 입력' 모드로 업체·절단서·실측무게를 등록(바로 완료/미납 상태로).

### 5.4 작업목록 (프론트+작업장 공용, 작업장은 로그인 없음)
- 진행 중 오더 카드 목록(상태별 색상), 절단→무게 입력→[확인], 제작은 이어서 [제작 완료].
- 확인 시 서버 기록 + 프론트 알림. 프론트는 지시 내용·무게 오입력 수정 가능(수정 이력 기록).
- **도면 보기**: 별도 창으로 three.js HTML 3D — 확대/축소/이동/회전, 우측 패널에서 바별 숨김/표시.
- 작업장 권한: 무게 입력/완료만. 오더 삭제·금액·미납 정보는 노출 안 함.

### 5.5 설정 (프론트)
`bar_database` 추가/수정/삭제, 직원/PIN/기기 관리(관리자), 작업장 PIN 발급, 알림 켜기(푸시 구독).

## 6. 서버 API (개요)
- `POST /api/auth/login`(PIN → 기기 토큰), `/api/admin/*`(직원·PIN·기기 관리).
- `GET/POST/PATCH /api/orders`, `POST /api/orders/:id/cut-weight`, `POST /api/orders/:id/complete`, `POST /api/orders/:id/pay`.
- `GET /api/dashboard/{unpaid,monthly,usage,by-company}`.
- `GET/PUT /api/bars`.
- `POST /api/ingest/blender` (API 키): JSON 절단서 + HTML 도면 → D1 + R2 저장 → 확정 오더 생성 → 알림.
- `GET /api/drawings/:key` (R2 프록시), `WS /api/ws`, `POST /api/push/subscribe`.

## 7. 비기능 요구
무료 티어 내 운영(Workers/D1/R2/KV/DO 무료 한도), HTTPS, 비밀번호 해시(PBKDF2 등), API 키는 Workers Secret, CORS는 GitHub Pages 도메인만 허용, D1 백업 방법(주기적 내보내기) 확인, 도면 HTML은 샌드박스 iframe/새 창으로 열기.

## 8. 단계별 개발 계획 (제안)
1. 서버 골격: D1 스키마, 인증, bars/orders API.
2. 프론트: 작업지시서 + 작업목록(+무게 입력·완료 흐름) + 설정.
3. 대시보드 4종 + 업체별 미납 인쇄.
4. 3D 도면 뷰어 템플릿(three.js, 바 표시/숨김) + Blender ingest API/클라이언트 스크립트.
5. 알림(WebSocket + Web Push) 및 PWA 설치 안내.
6. 실제 사용자 테스트(고령/비숙련 사용자 시나리오) 및 배포(GitHub Pages, Workers).

## 9. 2차 확정 사항
- 무게: **오더 전체 총무게 1회 입력** (행별 무게 컬럼 불필요, 이론무게는 참고 표시).
- 납입: **건별 완납만** (부분/일괄 납입 없음).
- 자재: **재고 관리 없음, 사용 내역(많이 쓴 순)만 표시.** `bar_database` 재고 컬럼·신청 기능은 제외, '부족 자재 신청'은 사람이 사용내역 보고 판단.
- 작업장 접근: PIN, 최초 1회 입력 후 기기에 기억 (9-2절에서 6자리로 최종 확정).

## 9-1. 3차 확정 사항 (무게 계산·알림)
- 단위: 길이 **mm**, 바 무게 **kg/m**. 이론무게 = kg/m × 길이/1000 × 수량.
- 작업지시서 진입 시 `bar_database`를 1회 로드해 브라우저에서 즉시 계산(서버 호출 없음), 목록은 로컬 캐시(오프라인 대비).
- 바 이름은 목록 선택 방식(자유 입력 금지), 목록에 없으면 '새 바 등록' 안내.
- 이론무게는 오더 저장 시점 값으로 기록(이후 kg/m 변경에 영향받지 않음), 실측무게는 별도 저장하며 미납 목록은 실측값 사용. 이론 대비 오차가 크면 경고 표시.
- Blender 전송 건에 미등록 바가 있으면 오더는 받되 프론트에 '미등록 바' 경고 표시.
- 알림: **WebSocket(화면 켜짐) + Web Push(화면 꺼짐)** 로 진행. iPhone은 PWA 설치 안내 제공. 사용 기기가 아이폰 위주면 텔레그램 봇으로 교체 가능하도록 알림 모듈 분리.

## 9-2. 인증 최종 확정 (이전 ID/비밀번호 방식 대체)
- **PIN 로그인 하나로 통일**, 서버가 PIN으로 역할(관리자/직원/작업장)과 직원을 식별. 직원/작업장 모두 **6자리**.
- PIN은 관리자만 발급: 설정>직원 관리에서 서버가 무작위 6자리 생성 후 1회만 표시, DB에는 해시만 저장. 자체 PIN 생성/가입 기능 없음. 분실 시 관리자가 재발급(기존 PIN·등록 기기 즉시 무효), 퇴사 시 비활성화.
- PIN은 서로 중복 불가(직원 간, 직원-작업장 간).
- 최초 PIN 입력 시 기기 토큰 발급 → 이후 자동 로그인(장기 유지, 사용 시 연장). 토큰에 역할 포함, 서버가 권한 강제(작업장 토큰은 작업목록 API만 허용).
- 무차별 대입 방지: 기기/IP별 5회 실패 시 잠금, 관리자가 해제. 로그인 이력 기록.
- 관리자 기능: 직원 등록/비활성화, PIN 재발급, 등록 기기 목록·해제, 작업장 PIN 변경 및 전체 기기 해제.
- 수정 이력(audit_log)에 직원 이름 기록. `users` 테이블: id, 이름, 역할, pin_hash, 활성, 기기토큰 테이블 별도.

## 10. 남은 확인 사항 (구현 전 협의)
- 도면 HTML 규격: three.js 내장 방식(CDN vs 인라인), 바 이름을 메타데이터로 포함해 숨김/표시 패널이 자동 생성되도록 하는 규약.
- 오더 취소/삭제 정책, 색상 마스터 목록 여부, 커스텀 도메인 사용 여부, 텔레그램 대안 필요 여부(iPhone 푸시).
- Blender 전송 시 업체명·작업구분을 AI 지시문에서 받는 형식.

## 11. 기술 스펙 (확정)
- 모노레포(npm workspaces): `server/`(Cloudflare Workers), `web/`(프론트), `blender/`(전송 스크립트·3D 뷰어 템플릿). 전부 TypeScript.
- 서버: Hono, Zod, D1(migrations/*.sql), R2, KV, Durable Object(WebSocket), Web Push(VAPID, Web Crypto), PBKDF2 PIN 해시, 기기 토큰은 Authorization 헤더, Blender는 X-API-Key.
- 프론트: Vite + React + TypeScript, TanStack Query, Tailwind CSS, 해시 라우팅, vite-plugin-pwa, 인쇄는 print CSS. GitHub Actions로 GitHub Pages 배포.
- 3D 도면: three.js 내장 단일 HTML, 바 목록은 `window.__BARS__` JSON, sandbox iframe/새 창으로 열기.
- 테스트: Vitest(@cloudflare/vitest-pool-workers), ESLint, Prettier.

## 12. 변경 이력
- 도면 저장소를 R2에서 **KV**로 변경(R2는 결제 수단 등록이 필요해 무료 운영 조건과 맞지 않음). 키는 `drawing:{orderId}`, 값 한도 25MB. 저장소 접근은 `server/src/drawings-store.ts` 한 곳에 모아 두어 나중에 R2로 되돌리기 쉽다.
- D1 이름은 계정에 같은 이름의 기존 DB가 있어 `whasung-agency` 로 생성.

## 13. 화면·단가 개정 (v0.2)
- **색상**은 화이트/블랙/실버/헨켈 4종 + 기타(v0.5 추가) 고정. 절단서의 모든 줄에 색상이 필요하다.
- **오더 하나 = 색상 하나.** 절단 작업에 색상이 섞이면 서버가 색상별 오더로 나누고 `group_id`로 묶는다(도면은 하나를 공유). 제작 작업은 색상 하나만 허용(여러 색이면 지시서를 나눈다).
- **색상별 kg당 단가**(`color_prices`, 이력 테이블): 설정에서 수정. 변경 시각 이후에 지시된 오더부터 새 단가가 적용되고, 이전 오더는 지시일 기준 단가가 유지된다. 처음 등록한 단가는 기존 오더에도 적용. **금액은 저장하지 않고** 조회할 때 `실측무게 × 지시일 기준 단가`로 계산해 작업지시서 견적, 미납 거래내역, 업체별 미납(명세)에만 표시한다.
- 작업지시서: '작업내용' 삭제, 작업 종류는 절단/제작 목록창, 제목과 입력을 한 줄에 배치, 바 이름은 입력한 글자와 가까운 후보를 골라 선택, 예상 견적가는 색상별 단가로 자동 계산.
- 작업목록은 진행중(대기/제작중)만 표시. 미납/완납은 대시보드에서 확인.
- 대시보드 탭 순서: 월간 거래내역 → 미납 거래내역 → 업체별 미납 → 자재 사용내역(명세 닫기 버튼 추가).
- 설정: 알림, 색상별 단가, 직원/PIN/기기(관리자), 로그아웃, **바(자재) 목록은 맨 아래**.
- 화면 톤: 블랙 + 실버 모노톤, 이모지·둥근 모서리 최소화.
## 14. 화면 개정 (v0.3)

## 15. 1~4단계 개정 (v0.4)
- **제작비용**: `orders.make_cost`(원, 한 칸). NULL=미입력, 0=0원 입력. 제작 작업만, 완납 전까지 입력·수정. 합계 = 판매금액(실제무게×지시일 단가) + 제작비용. 업체별 미납에는 "제작비용 미입력 N건" 표시.
- **업체 정보**: `companies`(이름, 전화(선택), 이메일). 작업 접수 시 새 업체명 자동 등록, 작업지시서 업체명 자동완성, 이름 변경·합치기(작업의 업체명도 함께 변경), 거래 있는 업체는 삭제 불가.
- **묶음 납입**: `POST /api/orders/pay-batch`(전부 미납일 때만 한 번에 처리). 미납 카드의 "같은 지시서 함께 납입", 업체별 명세의 체크 선택 납입(같은 지시서는 함께 체크).
- **한국 시간 집계**: 월간·자재 사용·판매분석 모두 지시일을 UTC+9 로 바꿔 센다.
- **이메일 전송(메일 앱 열기)**: 서버가 보내지 않고 `mailto:` 로 사장님 메일 프로그램을 연다. 업체 이메일이 없으면 입력창 후 업체 정보에 저장. 내용이 길면 클립보드 복사. 미납·월간 건별, 업체별 명세 전체.
- **판매분석**(`GET /api/analytics`): 년간(월별)/월간(일별), 자재 사용(환산수량 6m)·거래내역(판매금액+제작비용)·업체별 의뢰건수·업체별 판매량(무게). 지시일 기준.
- **데이터 보관(관리자)**: 전체 백업(JSON), 거래 장부(CSV, 엑셀용 BOM), 오래된 도면 보관·정리(`/api/admin/archive/*`). 완납 후 N개월이 지난 도면만 대상, 내려받은 파일의 sha256 이 서버 파일과 같을 때만 서버(KV)에서 지우고 작업에는 `drawing_archived_at` 만 남긴다("도면 보관됨"). 도면을 다시 올리면 표시가 지워진다.

- 월간 거래내역 정렬: 대기(진행중) → 미납 → 완납, 같은 상태는 지시일이 늦은 것부터.
- 미납 거래내역에 업체 조회(선택한 업체만 보기, 합계도 그 업체 기준).
- 업체별 미납 명세: 버튼을 위로 모음 — 인쇄하기 / 이메일 전송 / 선택거래 수정(한 건씩) / 선택거래 납입처리 / 명세닫기.
- 작업목록 카드: 세부내역·내용 수정 버튼을 카드 오른쪽 위로 옮겨 카드 높이를 줄임.
- 작업지시서: 절단서를 표 형태로 단순화(바별 예상무게 표시 없음). 총 예상무게·견적은 아래에 그대로.
- **미납이 된 절단 → 제작으로 변경**: 내용 수정에서 작업 종류를 제작으로 바꾸면 미납에서 빠지고, 절단은 끝난 상태(무게 유지)로 작업장의 '제작중'에 넘어가며 작업장에 알림. 제작 완료를 누르면 다시 미납. (대기 상태의 절단은 종류만 바뀌어 대기로 남는다.)
- 제작중인 건을 절단으로 바꾸면(내용 수정) 제작 작업은 취소되고 바로 미납으로 이동, 제작비용은 지워진다.
- 제작비용(0원 포함)을 입력하지 않은 제작 작업은 납입할 수 없다: 미납 거래내역은 납입 버튼 대신 안내를 보이고, 업체별 명세의 선택 납입도 막으며, 서버(`/pay`, `/pay-batch`)도 409 로 거절한다.
- 판매분석 "바 종류별 사용량"은 예상 무게가 많은 순(환산수량·길이는 보조 표시).
- 색상에 **기타** 추가(5종): 작업지시서·단가 설정·Blender 업로드(뷰어는 올리브색)에서 선택. 색상이 없는 옛 작업은 판매분석에서 기타로 센다.
- 판매분석 자재 사용내역: 환산수량 대신 예상 무게 표시, 기간별 실제 무게 그래프와 바 종류별 사용량(예상 무게순)을 색상별로 나눠 그린다.
- **도면 삭제(백업 → 삭제로 변경)**: 완납 후 지정한 기간(기본 12개월, 설정>데이터 보관에서 변경)이 지난 도면은 백업 없이 서버(KV)에서 지운다. 같은 지시서의 작업이 모두 완납일 때만. 작업에는 '도면 삭제됨' 표시만 남는다. 매일 한국 시간 00:00 자동 실행(cron, 한 번에 최대 40개), '지금 삭제' 버튼으로 수동 실행도 가능. 내려받기·sha256 확인 절차는 없앴다.
- **직원 삭제**(관리자): 사용 중지한 직원만 삭제할 수 있다. 등록 기기·푸시 구독도 함께 지우며, 관리자·작업장 계정과 자기 자신은 삭제 불가. 수정 이력의 직원 이름은 문자열로 남는다.
- **추가 단가(원/kg)**: 자재 값이 더 비싼 바(방범창 4023(25X25)-상/하단바·-중간바 등 +500)를 설정 > 바 목록에서 지정. 그 바가 한 줄이라도 들어간 작업은 색상 단가 + 추가 단가를 **작업 전체 실제 무게**에 적용한다. 작업이 만들어질 때(절단서를 고칠 때) 값이 작업에 고정되어 바의 추가 단가를 나중에 바꿔도 접수된 작업은 그대로이며, 변경 이력은 두지 않는다. 단가 표시는 "3,500원/kg (추가 +500 포함)". 마이그레이션 0006.
- **이메일 도면 첨부(선택)**: 도면이 있는 거래의 이메일 전송 때 "도면도 함께 보낼까요?"를 묻는다. 메일 작성 주소에는 파일을 실을 수 없어서, 선택하면 도면(.html)을 내 컴퓨터에 먼저 저장하고 작성 창을 연 뒤 클립 버튼/끌어다 놓기로 직접 첨부하도록 안내한다. 같은 지시서의 색상별 작업은 도면 한 파일만 담고, 서버에서 삭제된 도면은 후보에서 빠진다.
- 이메일 폰 대응: 폰(안드로이드·iOS)에서는 웹 메일 작성 페이지 대신 폰의 메일 앱을 연다. Gmail=안드로이드 mailto(Gmail 앱)/iOS googlegmail://, Outlook=ms-outlook://compose, 그 밖=mailto(네이버·다음은 내용 복사 병행). 컴퓨터는 기존 웹 작성 페이지. 폰 실기기 확인 전.
- **카톡으로 내용 전송(문구 복사)**: 이메일 전송 버튼 옆에 "카톡으로 내용 전송"(명세는 "카톡 전송"). 누르면 카톡용 문구가 보이고 "문구 복사하기"로 복사해 카카오톡 대화방에 붙여넣는다. 도면이 있으면 "도면 보기 링크도 함께 보내기"를 고를 수 있고, 링크는 7일 유효한 서명 링크(`GET /orders/:id/drawing-link?days=N`, 직원·관리자만 최대 30일, 작업장은 10분 고정). 링크를 아는 사람은 누구나 열 수 있고, 도면이 서버에서 삭제되면 열리지 않는다.
- **메일·카톡 문구 통일**: 모두 "안녕하세요. 화성알루미늄입니다." 인사말 → 본문 → 감사합니다/서명 순서(업체명 "담당자님께" 줄 없음). 업체별 미납 명세는 건별 카드형(한 건 = 날짜·구분/색상, 무게×단가=금액, 제작비용, 계)으로 폰·카톡에서도 줄이 꺾이지 않게 한다. 표 모양은 글자 폭이 달라 깨져서 쓰지 않는다.
- **월간 거래내역에서도 납입**: 미납 건에 납입 버튼(확인창 후 완납 처리). 제작은 제작비용(0원 포함)이 입력되어야 버튼이 나오고, 비어 있으면 안내 문구만 보인다(서버도 거절).
- **판매분석 기준 정리(v0.6)**: 월·년에 넣는 기준은 항상 **지시일**(한국 시간)이다. 지시일이 10/31 이면 무게 입력·납입이 11월 이후여도 10월에 들어간다.
  - 자재 사용내역은 **무게가 입력된 작업만** 센다: 카드 = 예상 무게(절단서 기준) / 실제 무게 / 총 사용 길이 / 바 종류. 일별(월별) 실제 무게 그래프는 색상별. 바 종류별 사용량은 같은 작업만, **예상 무게** 많은 순, 색상별.
  - 거래내역은 상태별 카드: 완납 건수(완납 무게·금액) / 미납 건수(미납 무게·미납 금액) / 진행 건수(대기·제작중, 예상 무게만, 금액 없음) / 제작비용 미입력. 금액 = 실제 무게 × 단가 + 제작비용. (절단 금액·제작 금액 카드는 삭제)
  - 그래프: 일별(월별) **완납** 거래 금액(완납만, 절단/제작), 일별 거래 건수는 완납(노랑)·미납(빨강)·진행(검정) 색으로 쌓아서 표시.
  - 업체별 의뢰건수·판매량(무게)도 완납(노랑)/미납(빨강)/진행(검정)으로 나눠 표시. 판매량은 완납·미납은 실제 무게, 진행은 예상 무게.
